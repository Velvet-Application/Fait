# Charte graphique mobile — version validée

## Statut

La direction visuelle **Concept 3 — Sceau de confiance** est validée comme base officielle de FAIT. pour les applications natives iPhone et Android.

La marque reste soumise à une vérification juridique distincte portant sur le nom, le symbole et les classes de dépôt.

## Identité

### Nom

**FAIT.**

Le point final appartient au logotype et exprime l'accomplissement.

### Signature

> **Vous demandez. C'est fait.**

### Symbole

Un sceau souple et arrondi contenant un cercle et une coche de validation.

Le symbole doit évoquer simultanément :

- la confiance ;
- la protection ;
- l'accompagnement ;
- la validation ;
- la résolution complète d'une démarche.

Il ne doit pas ressembler à une simple icône de liste de tâches, à un badge promotionnel ou à un label administratif rigide.

## Palette officielle

| Rôle | Nom | Hex |
|---|---|---|
| Couleur principale | Vert confiance | `#2E6B4F` |
| Couleur secondaire | Sauge douce | `#A8C5B0` |
| Fond principal | Blanc chaleureux | `#FAF7F2` |
| Neutre chaud | Gris taupe | `#CFC6B8` |
| Texte et fond sombre | Olive charbon | `#2B2E28` |

Les couleurs de statut peuvent compléter cette palette :

- **À traiter** : beige chaud ;
- **En cours** : bleu doux ;
- **Besoin de vous** : orange doux ;
- **Fait** : vert doux.

Ces couleurs restent fonctionnelles et ne remplacent jamais la palette de marque.

## Typographies

### Principale — Satoshi

Usage :

- logotype ;
- titres ;
- messages courts ;
- boutons et éléments importants.

### Secondaire — Inter

Usage :

- interface ;
- textes courants ;
- formulaires ;
- contenus informatifs ;
- données et statuts.

Une police système peut être utilisée temporairement pendant le développement, mais le rendu final doit conserver les métriques et la hiérarchie définies dans la charte.

## Principes d'interface

1. Une hiérarchie immédiatement compréhensible.
2. Des cartes aérées et peu chargées.
3. Une action principale clairement identifiable par écran.
4. Des statuts toujours visibles et accompagnés d'un libellé.
5. Des boutons suffisamment grands pour un usage à une main.
6. Des contrastes conformes aux règles d'accessibilité.
7. Aucun écran ne doit donner une impression administrative froide ou anxiogène.
8. L'utilisateur doit toujours comprendre ce qui est fait, ce qui reste à faire et ce qui attend son accord.

## Composants structurants

### Bouton principal

- fond Vert confiance ;
- texte clair ;
- coins arrondis ;
- libellé orienté action : **Confirmer**, **Valider**, **Confier**, **Envoyer**.

### Bouton secondaire

- fond clair ou transparent ;
- contour Vert confiance ;
- texte Vert confiance.

### Cartes dossier

Chaque carte doit présenter au minimum :

- le nom du dossier ;
- l'organisme ou la catégorie ;
- le statut ;
- la prochaine action ;
- la date de dernière mise à jour.

### Statuts officiels

1. **À traiter** — une action doit être planifiée.
2. **En cours** — la démarche est en traitement.
3. **Besoin de vous** — une validation ou une information utilisateur est requise.
4. **Fait** — la démarche est finalisée et une preuve est disponible.

## Particularités iPhone

- application native respectant les zones sûres et les tailles dynamiques ;
- navigation principale par onglets bas lorsque le parcours le justifie ;
- gestes, transitions et retours cohérents avec les habitudes iOS ;
- interface aérée, claire et sobre ;
- support du mode sombre et de l'accessibilité dynamique ;
- icône fournie sans arrondi intégré dans le fichier source : iOS applique son propre masque ;
- aucun texte ni détail fin dans l'icône ;
- symbole centré avec une marge de sécurité généreuse ;
- déclinaisons d'icône adaptées aux modes clair, sombre et teinté selon les capacités de la version iOS ciblée.

## Particularités Android

- application native respectant les principes Material sans devenir une copie générique de Material ;
- icône adaptative composée d'un premier plan et d'un arrière-plan séparés ;
- symbole conservé dans la zone de sécurité pour résister aux différents masques des constructeurs ;
- composants flexibles adaptés aux différentes tailles et densités d'écran ;
- support du mode sombre, des tailles de texte et de la navigation système ;
- retours tactiles et états pressés cohérents ;
- contraste légèrement renforcé lorsque nécessaire pour préserver la lisibilité.

## Icône d'application

### Construction

- fond Blanc chaleureux ou Sauge douce ;
- sceau Vert confiance ;
- cercle et coche clairs ;
- aucun mot, aucune initiale, aucun contour superflu ;
- forme lisible à très petite taille.

### Règles

- ne pas étirer le symbole ;
- ne pas modifier les proportions ;
- ne pas ajouter d'ombre dure ;
- ne pas utiliser de vert fluorescent ;
- ne pas placer le symbole trop près des bords ;
- ne pas recréer manuellement les coins arrondis iOS dans l'actif maître.

## Ton de marque

> Une présence fiable qui simplifie, sécurise et finalise les démarches du quotidien.

Le ton doit être :

- clair ;
- calme ;
- direct ;
- rassurant ;
- jamais infantilisant ;
- jamais exagérément technologique.

## Livrables à produire avant publication

- logo horizontal clair et sombre ;
- logo compact ;
- symbole seul en vectoriel ;
- icône maître iOS haute définition ;
- premier plan et arrière-plan Android adaptatifs ;
- favicon et icônes web ;
- splash screen ;
- jeu de composants UI ;
- tokens de couleurs, espacements, rayons et typographies ;
- règles d'accessibilité et de mode sombre.
